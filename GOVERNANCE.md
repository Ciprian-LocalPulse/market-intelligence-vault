# Governance

Ciprian Ștefan Pleșca is the project steward, principal author and current maintainer. He has final
authority over scope, methodology, code acceptance and releases. No institutional endorsement or
external governance body is claimed. Collaboration is subject to [LICENSE.md](LICENSE.md).

Methodology changes require an explicit proposal with affected formulas, assumptions, evidence,
tradeoffs, worked examples, model versioning and migration impact. Security changes require threat
analysis and negative tests. Breaking changes require prominent release notes and transition guidance.
Do not silently alter CSV contracts, score orientations, floors/caps, approval semantics or sample status.

Changes should be reviewable through a PR and the [contribution guide](CONTRIBUTING.md). Release
authority belongs to the maintainer after validation, security review and branch-rule inspection.
Branch protections must not be disabled or bypassed. Published tags must not be force-moved.
Documentation is part of the change, not deferred release cleanup.

Repository release approval does not authorize a strategic action. Engagement decision authority,
dated risk acceptance and bound sign-off remain separate responsibilities of the appropriate owner.
